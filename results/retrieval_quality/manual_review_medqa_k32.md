# Manual review: MedQA-US, RRF-2, k=32, "only wrong options in context"

All 25 questions where (1) only wrong options occur in the 32 retrieved snippets (lexical proxy),
(2) CoT answered correctly and (3) RAG switched to a wrong option that occurs in the context.
For each, the first snippet that mentions the chosen option was read together with the RAG reasoning.
Generated by `scripts/retrieval_quality.py` logic; snippets and reasoning were read by the
repository's AI assistant (one annotator, no second rater), so labels are a qualitative check, not ground truth.

Labels:
- **lure**: the snippet describes the wrong option in a clinical picture that overlaps with the question (a "near-miss" retrieval)
- **topical**: same topic, the option is mentioned but the snippet does not describe the question's picture
- **incidental**: the option is mentioned in an unrelated context
- **proxy error**: the correct answer is in fact present (spelling variant); the case should not be in this group

**Reading.** In most cases (80%) the retrieved text is on the question's topic but describes a
neighbouring diagnosis or treatment: question-only retrieval matches the symptoms, and textbooks
describe the same symptoms under the differential diagnoses. The model then adopts the condition

up genuinely misleading context. One case was a proxy error ("Ewing's" vs "Ewing").
